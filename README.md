# Student–Project Allocation (EURECOM, Spring 2026)

MILP-based allocation of students to research projects for the EURECOM
Data Science semester project course. Extends the previous team's solver with lower-bound
enforcement, partner constraints, a tunable track-mismatch penalty, five
fairness criteria, one-sided stability, and full data loading from the raw
administration files.

## Setup

```bash
python3 -m venv venv
source venv/bin/activate          # Windows WSL / Linux / macOS
pip install pulp pandas openpyxl odfpy matplotlib
```

## Usage

Run in order:

```bash
python3 src/load_2026_data.py     # 1. build the validated dataset
python3 src/generate_report.py    # 2. baseline allocation → output/allocation_2026.xlsx + charts
python3 src/compare_criteria.py   # 3. compare the five criteria → charts + pickle
python3 src/compare_penalty.py    # 4. track-penalty sweep → charts
python3 src/explain.py            # 5. per-student explanations → explanations.xlsx + txt
python3 src/whatif.py             # 6. what-if / sensitivity → whatif_report.txt + chart
```

## Enabling the track penalty

1. Fill the `track` column in `data/student_tracks.csv` (one of the six
   EURECOM tracks per student; the file is keyed by email).
2. Call the engine with a positive `λ`, e.g. in a script:

```python
from spa_milp import load_data, load_student_tracks, solve
data   = load_data()
tracks = load_student_tracks()
res    = solve(data, criterion="minimax_weighted",
               track_lambda=50, student_tracks=tracks)
```

With no track data the penalty is simply inactive and the model behaves as the
baseline.

## The engine in one call

`spa_milp.solve()` is parameterised by:

| Argument | Default | Meaning |
|----------|---------|---------|
| `criterion` | `"minimax_weighted"` | `minimax_weighted`, `minimax`, `weighted`, `exponential` |
| `track_lambda` | `0.0` | weight of the track-mismatch penalty |
| `student_tracks` | `None` | dict from `load_student_tracks()` |
| `enforce_stability` | `False` | add one-sided stability constraints |
| `enforce_partners` | `True` | keep partner groups together |
| `enforce_lower_bounds` | `True` | use the `y[p]` open/close variable |

It returns a results dict with the assignment, rank distribution, satisfaction,
opened projects, partner status, track stats, and a stability audit.

## Key results (Spring 2026 data)

- Baseline: 42 / 11 / 5 at ranks 1 / 2 / 3 → **81.9 % satisfaction**, all 58
  assigned, 8 / 9 partner groups together.
- Minimax-alone collapses to 62.9 % — confirming it must be combined with a
  weighted term.
- Four criteria converge to 81.9 % because students rank only three projects;
  recommendation is to ask for 5–7.
- Track penalty `λ=50` removes all mismatches for a 2.6-point satisfaction cost.

See `docs/Technical_Report.md` for the full analysis.
